A page with music on it

gscore running as a player: the score is engraved and played in the browser, with nothing on screen that could change it.

A score, with a play button

Only the score

With player=bare there is no transport at all: the score itself is the button, and clicking it starts and stops the music.

loop=1 makes it go round again, which is what you want for something to practise along with.

One line instead of a page

The two above are wrapped to the frame: the music is broken into systems as wide as the frame and the frame scrolls down, which is how a page of music is read. mode=strip draws it as one unbroken line instead, and the frame scrolls sideways.

Wrapped is better for music somebody is going to read — an exercise, a study, a piece — because a reader following a line of notes should not have to scroll sideways to do it. The line is better for a band across a page, for the one bar quoted in the middle of a sentence, and for something to play along with: the music runs past as it sounds instead of jumping from line to line.

Everything you can put in the address

After the ?, joined with &. Only score= is needed; the rest have defaults.

score=URL The file to open. Resolved against the gscore page, not against yours, which is why the frames here reach back out with ../../. An absolute URL always works
player=1 No menus, no palette, no inspector: the score and a play button
player=bare Not even that — the score itself is the button
mode=strip One unbroken line, scrolling sideways. Left out, the music is wrapped to the width of the frame
zoom=N Staff space in pixels: 8 is the default, 12 is large
loop=1 Start again at the end
autoplay=1 Start as soon as the browser allows it. A browser makes no sound until the reader has clicked something, so this is a request rather than an instruction: refused, the first click on the page plays it
tune=N Which tune of a book to show, counted from 0

Tall enough for the music

None of the frames on this page is given a height. A number would be a guess, and a guess is wrong as soon as the music changes: this exercise is written for three flutes, and the 200 pixels that fitted a single line showed two of them and the top of the third.

The frame knows better, because it is the thing that drew the music. When it is ready it says how tall the drawing came out, and the page sets the height from that: 

<iframe class="score" src="…?player=1&score=tune.abc"></iframe>

<script>
  window.addEventListener("message", (e) => {
    if (!e.data || e.data.gscore !== "ready") return;
    for (const f of document.querySelectorAll("iframe.score")) {
      if (e.source === f.contentWindow) f.style.height = e.data.system + "px";
    }
  });
</script>

system is one system of every instrument — all the staves that sound together — which is the unit music is read in and the right height for a frame. height is all of the music, which is what you would use for a frame with no scrollbar at all; on a long piece that is a frame as long as the piece.

The script form below does this for you and needs no code at all: give the <div> no data-height and the frame comes up the right size by itself.

Driving it from the page

The player answers messages, so your own buttons can run it. This is how to replace a player you have already written without rebuilding the page around it. 

<iframe id="score" src="https://stricaud.github.io/gscore/?player=1&score=tune.abc"></iframe>

<script>
  const frame = document.getElementById("score");
  frame.contentWindow.postMessage({ gscore: "play" }, "*");
</script>

Every message carries a gscore key, so nothing else travelling between your page and the frame can be mistaken for one. Anything gscore does not recognise is ignored rather than guessed at.

{ gscore: "play" } Start, from the beginning
{ gscore: "stop" } Stop
{ gscore: "toggle" } Play, or pause where it is
{ gscore: "mode", value: "strip" } One unbroken line, or "page" to wrap it to the frame again. The music stays where it is, so a reader following it does not lose their place
{ gscore: "zoom", value: 10 } Staff space in pixels
{ gscore: "tune", value: 3 } Show tune 3 of a book, counted from 0
{ gscore: "load", value: "x.abc" } Open another score, by address
{ gscore: "open", value: "X:1\n…", name: "tune.abc" } Open one written into your page. Text for ABC and MusicXML, bytes for the zipped formats

And two it sends back to you:

{ gscore: "ready", … } The score is up and may be sent to. It carries title, the name of the piece; tunes, how many are in the book; height, how tall all the music came out; and system, how tall one system of it is — which is the height to give the frame
{ gscore: "ended" } The music reached the end
<script>
  window.addEventListener("message", (e) => {
    if (e.source !== frame.contentWindow) return;
    if (!e.data || e.data.gscore !== "ready") return;
    frame.style.height = e.data.system + "px";   // as tall as one system
  });
</script>

What it reads

Whatever gscore reads: ABC (.abc), MusicXML (.musicxml, .xml, .mxl), MuseScore (.mscz, .mscx), NoteWorthy Composer (.nwc, .nwctxt), GUIDO (.gmn), Finale (.musx) and gscore's own .gscore.

The file is fetched by your page and read in the reader's own browser. Nothing is uploaded anywhere, and there is no server behind any of it: gscore itself is the editor compiled to WebAssembly, so the frame is doing the engraving and the playing on the reader's machine.
